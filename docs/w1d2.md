## 一、set 方法速查

| 用法 | 作用 | 注意 |
|---|---|---|
| `set()` | 创建空集合 | `{}` 是空字典，不是空集合 |
| `{1, 2, 3}` | 字面量创建 | 重复元素自动去掉 |
| `x in s` | 成员检测 | O(1)，这是 set 最大的用处 |
| `s.add(x)` | 加单个元素 | 已存在则无变化，不报错 |
| `s.update(可迭代)` | 批量加 | `s.update("abc")` 加的是 a、b、c 三个字符 |
| `s.remove(x)` | 删一个 | 元素不存在 → `KeyError` |
| `s.discard(x)` | 删一个 | 元素不存在 → 静默不报错（清理数据更省心） |
| `s.pop()` | 随机弹出一个 | 集合无序，别指望弹哪个 |
| `s.clear()` | 清空 | |
| `a \| b` / `a & b` / `a - b` / `a ^ b` | 并 / 交 / 差 / 对称差 | 教程 5.4 里的重点 |

一句话记：**查重用 `in`，加用 `add`，批量加用 `update`，删用 `discard`。**

## 二、dict 方法速查

| 用法 | 作用 | 注意 |
|---|---|---|
| `d = {}` | 空字典 | 与空集合相反 |
| `d[key]` | 取值 | 键不存在 → `KeyError` |
| `d.get(key)` | 取值 | 键不存在 → 返回 `None`，不报错 |
| `d.get(key, 默认值)` | 取值 | 键不存在 → 返回你给的默认值 |
| `d[key] = value` | 新增/修改 | 键存在就覆盖，不存在就新增 |
| `key in d` | 判断键是否存在 | 注意是判断**键**，不是值 |
| `del d[key]` | 删除 | 键不存在 → `KeyError` |
| `d.keys()` / `d.values()` / `d.items()` | 键视图 / 值视图 / 键值对视图 | 配合 for 遍历 |
| `d.setdefault(key, 0)` | 取键，不存在则先设默认值 | 计数时常用，可省一次 if 判断 |

一句话记：**不确定键在不在，就用 `get`，不要用 `d[key]`。**

## 三、四个必答问题

**1. 什么时候该用 `set` 而不是 `list`？**
需要①去重、②快速判断“某个东西是否存在”、③做集合运算（并交差）时用 set；需要保持顺序、按下标访问、允许重复时用 list。
`x in list` 要逐个扫（O(n)），`x in set` 靠哈希直接定位（O(1)），数据量大时差别明显。
我自己的话：只判断在不在而对排序无要求时用set（）
> **批改 ✅ 方向对，漏了两条**：set 还有两个核心用途——①**去重**（`set(列表)` 一步搞定）；②**集合运算**（并/交/差）。你答的「判断在不在」是第三条。补全记法：**去重、判存在、做运算 → set；保顺序、按位置取、许重复 → list。**

**2. `d.get(k)` 和 `d[k]` 什么时候必须用前者？**
键可能不存在时必须用 `get`。例如统计词频时第一次遇到的词还不存在，`d[word] += 1` 会先抛 `KeyError`；用 `d[word] = d.get(word, 0) + 1` 就安全。
`d[k]` 适合“键一定存在”的场景，写起来更短。
我自己的话：不确定k中是否有对应的键时用get（）
> **批改 ✅ 正确，一句话到位。** 只补一层因果：`d[k]` 本质是「我保证这个键在」，一旦不在就 `KeyError` 立刻崩；`get` 本质是「我先探一下，不在就给我个默认值」。这就是为什么计数时写 `d.get(word, 0) + 1` —— 第一次遇到的新词也有 0 打底。

**3. `for k, v in d.items()` 里的 `k, v` 是什么语法？**
是**多元赋值/解包**，和昨晚的 `result, seen = [], set()` 同一套机制。`items()` 每次给出一对 `(键, 值)`，元组自动拆给两个变量。
等价写法：`for pair in d.items(): k, v = pair`。
我自己的话：字典中的键值对分别拆给k，v
> **批改 ✅ 现象描述准了，术语缺一层**：这个语法叫**解包（unpacking）**，`k, v = pair` 把元组的两个元素分别绑给两个名字。和昨晚 `result, seen = [], set()` 是同一个机制，只是右边从字面量换成了 `items()` 吐出的元组。顺带记住它有个限制：**左边变量个数必须和右边元素个数相等**，否则 `ValueError`（`a, b = (1, 2, 3)` 就报错）。

**4. 统计词频，为什么字典比列表合适？**
列表按下标存，词和位置的对应关系是“猜不出来”的；字典是“词 → 次数”的直接映射，`d[word] = d.get(word, 0) + 1` 一步完成累加，查找也是 O(1)。
列表硬要做只能存 `(词, 次数)` 元组，每次累加还要先遍历找位置，复杂度 O(n²)。
我自己的话：字典词和字数一一对应，列表修改时需要遍历找到词的位置再改
> **批改 ✅ 核心判断对，措辞要改两处**：①「字数」应为「**次数**」（统计的是出现次数，不是字符长度）；②「一一对应」这个词容易误会成「词和词序号一一对应」，准确说法是**「词直接映射到次数」——拿词当键去查次数，一步到位，不需要知道它在第几位**。另外你说的「列表修改要遍历找位置」正是 O(n)，所以整体是 O(n²)。

## 四、为什么 set 里的元素必须可哈希、不能放列表

集合靠元素的哈希值决定存在哪个槽位。要求元素**不可变、哈希值稳定**：内容一变哈希就变，集合再也找不到它。
- 可哈希：数字、字符串、元组、`frozenset`、`None`
- 不可哈希：`list`、`dict`、`set`（都是可变的）

所以 `{[1, 2]}` 会报 `TypeError: unhashable type: 'list'`。要放一组值，先转元组：`{(1, 2)}`。

## 六、今天的疑问清单

**Q1 第二题（切词）没有头绪，不知道从哪下手**
> 切词 = 把一整段文本变成“干净的词列表”，顺序做三件事：转小写 → 去标点 → 按空白切开。三步对应 `s.lower()`、`s.replace(p, " ")`（或用 `str.maketrans` 批量换）、`s.split()`。`split()` 不传参数时按任意空白切，并自动丢弃空串，所以把标点换成空格后直接切就干净了。

**Q2 把标点换成空格，用 `str.maketrans` 怎么做？**
> `str.maketrans(from, to)` 是**产生一张对照表**，`s.translate(表)` 才**执行替换**，两步不能合并。
> 一对一（字符个数相等）：`s.translate(str.maketrans(",.!?", "    "))` —— 逗号点感叹号问号全部变空格。
> 多对一（标点各不相同却都要变同一符号）：`str.maketrans({p: " " for p in ",.!?;:"})` —— 传一个**字典**，键是要被换掉的字符，值是替换成的字符。
> 记忆点：**两个参数 → 等长逐字替换；一个字典参数 → 任意的“谁→谁变什么”。**

**Q3 `str.maketrans` 的具体用法看不懂**
> 它**不修改原字符串**，只返回一张表；必须配 `translate` 用。特点是一次扫描完成全部替换，比连续写 6 个 `replace` 快，而且不会因为“替换产物又被下一个 replace 命中”而出错。
> 两种写法最小示例：
> `str.maketrans("ab", "xy")` → 表：a→x、b→y
> `str.maketrans({"a": " ", "b": " "})` → 表：a→空格、b→空格
> 顺手记一个附带能力：`str.maketrans("abc", "xyz", "！？")` 第三个参数是**要删掉的字符**（映射为 None）。

**Q4 第三题：为什么这里用 `Counter` 比手写字典好？**
> 省的是**重复劳动 + 出错概率**：手写要自己 `for` 循环、自己 `get(word, 0) + 1`、自己排序取前 N；`Counter` 一行 `Counter(词列表)` 建好，`most_common(n)` 一步取榜单。
> 深层理由：统计词频是**极高频通用需求**，所以标准库把它做成了专门类型，还额外带了 `update`、加减运算、`total()`。工程习惯是：**标准库已经为你封装好的通用逻辑，不要自己重写。**
> 同时保留手写版的理由：面试和排错时要知道 `Counter` 内部就是一张普通字典。

**Q5 第三题、第四题的具体要求是什么？**
> 第三题 `count_with_counter(words) -> Counter`：接收词列表，返回 `Counter` 对象，用 `.most_common()` 能取榜单。
> 第四题 `count_manual(words) -> dict`：**不许用 `Counter`**，纯手动累加（`d[word] = d.get(word, 0) + 1`），返回普通字典。
> 两题输入输出形状一致，所以第五题的 `top_n` 必须两种都能吃 —— 这就是为什么它要用 `hasattr` 判断。

**Q6 `Counter()` 到底干什么？**
> 它是 `dict` 的子类，专门用来**数东西**：传一个可迭代对象进去，它立刻返回“每个元素 → 出现次数”。
> `Counter(["a","b","a"])` → `Counter({'a': 2, 'b': 1})`；也能传字典或关键字参数 `Counter(a=2, b=1)`。
> 因为是 dict 子类，普通字典的操作（取值、遍历、`in`）全都能用；额外多了 `most_common(n)`、`update()`、`+`/`-` 运算。取一个不存在的键不报错，返回 `0`，这点比普通 dict 更宽容。

**Q7 `c[word] = c.get(word, 0) + 1` 这行在干什么？**
> 拆成两半读：`c.get(word, 0)` 是「**先查**：word 之前数过几次？没数过就当 0」；`+ 1` 是「这一次又出现了一回」；`c[word] = ...` 是「**再写回**：把新次数存进去」。
> 为什么不能写 `c[word] += 1`：第一次遇到 `word` 时键还不存在，`+=` 内部要先取旧值，直接 `KeyError`。`get` 的默认值 `0` 就是这个坑的补丁。
> 一句话记法：**「查一下（缺省算 0）→ 加一 → 存回去」。**

**Q8 `sorted(counts.items(), key=lambda kv: kv[1], reverse=True)` 看不懂**
> 三件事合在一行：
> ① `counts.items()` 给出 `('hello', 3)` 这样的**元组**列表；
> ② 不写 `key` 时 sorted 按元组第一个元素（单词字母）排，得到的是字典序，不是排行榜。`key=lambda kv: kv[1]` 是**换尺子**：每对元组先用函数取出 `kv[1]`（次数），sorted 只拿这个数字比大小。`lambda kv: kv[1]` 等价于 `def f(kv): return kv[1]`，`kv` 只是个参数名；
> ③ `reverse=True` 从大到小。
> 并列时的顺序：sorted 是**稳定排序**，次数相同的词保持原字典的插入顺序，不跳。

**Q9 `[:n]` 能直接跟在 `sorted(...)` 后面吗？**
> 能。`sorted(...)` 的返回值本身就是**列表**，对列表切片是合法操作，所以 `sorted(...)[:n]` 就是“排完序立刻取前 n 个”。也可先赋给变量再切，效果一样。
> 数据量极大（几十万种词）时，全量排序浪费，可换 `heapq.nlargest(n, counts.items(), key=lambda kv: kv[1])`，只维护大小为 n 的堆，复杂度 O(m log n)。
