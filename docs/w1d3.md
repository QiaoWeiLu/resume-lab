## 一、正则分级：什么必须记，什么只要认得

判断标准：**今晚脚本用得到的算必记；以后写用例、筛日志会碰的算了解；面试才问的算暂不管。**

### 1. 必须记住（10 个，今晚全部用到）

| 语法 | 意思 | 在日志里对应什么 |
|---|---|---|
| `\d` | 一个数字 | 年份、日期、时分秒 |
| `\w` | 一个字母/数字/下划线 | `ERROR`、`perception` |
| `\s` | 一个空白（空格/制表/换行） | 字段之间的空格 |
| `.` | 任意字符（不含换行） | `msg` 的任意内容 |
| `+` / `*` / `?` | 前一项 1 次以上 / 0 次以上 / 0 或 1 次 | `\d+`、`\s+`、`-?` |
| `[ ]` | 里面任意**一个**字符 | `[0-9]`、`[A-Z]` |
| `( )` | 分组，圈住一段 | 圈住每个字段 |
| `(?P<name>...)` | **命名分组**，圈住并起名 | `groupdict()` 靠它取字段 |

外加两条操作层面的必知：

- **转义**：正则里的 `.`、`[`、`]`、`(`、`)`、`+`、`*`、`?` 天生是语法字符。要匹配字面的，前面加 `\`。日志里的方括号因此要写 `\[` `\]`，这是新手最容易错的地方。
- **四个函数的分工**：`re.search` 全文找第一处、`re.match` 只从开头比、`re.findall` 找全部返回列表、`re.compile` 预编译成对象。配合 `m.groupdict()` 一次性取全部命名分组。

### 2. 了解即可（认得、能说出大概作用，不要求默写）

| 语法 | 意思 | 什么时候用得上 |
|---|---|---|
| `{m,n}` | 重复 m 到 n 次 | 严格校验 IP / 时间格式时比 `+` 精确 |
| `\|` | 或，如 `ERROR\|FATAL` | 一次匹配多个级别 |
| `^` `$` | 行首 / 行尾 | 要“整行完全符合”时；逐行解析用 `search` 即可 |
| `\b` | 单词边界 | 提取独立单词、防误命中 |
| `*?` `+?` | 非贪婪（取最短） | 一行里有多个 `[...]` 时只取第一个 |
| `re.IGNORECASE` / `re.VERBOSE` | 忽略大小写 / 允许换行缩进与 `#` 注释 | VERBOSE 今晚已在用 |
| `\D` `\W` `\S` | `\d` `\w` `\s` 的反面 | 见到能认，不必背 |
| `re.sub` / `re.split` | 正则替换 / 正则分割 | 批量清洗日志文本 |

### 3. 暂不管（知道有这回事就行）

反向引用 `\1`、`(?P=name)`；前瞻后顾 `(?=...)`、`(?!)`、`(?<=...)`；内联标志 `(?i)`、条件分组；`\p{Han}` 之类 Unicode 属性；递归匹配。
这些不会在你现有任务里自然出现，学了也留不住，等真碰到再学。

## 二、把日志格式当图纸，一段一段翻译

正则不是背出来的，是**照着日志长相反推写法**。今晚这份日志 5 段，模式也是 5 行，一一对应：

```
日期            →  (?P<date>\d{4}-\d{2}-\d{2})
时间            →  (?P<time>\d{2}:\d{2}:\d{2})
级别            →  (?P<level>\w+)
模块（带方括号）  →  \[(?P<module>\w+)\]
消息            →  (?P<msg>.+)
段与段之间        →  \s+          ← 别漏，字段之间必有空白
```

拼起来就是 `tools\log_parse.py` 里那个 `LOG_RE`：

```python
LOG_RE = re.compile(
    r"""
    (?P<date>\d{4}-\d{2}-\d{2})\s+
    (?P<time>\d{2}:\d{2}:\d{2})\s+
    (?P<level>\w+)\s+
    \[(?P<module>\w+)\]\s+
    (?P<msg>.+)
    """,
    re.VERBOSE,
)
```

写正则时脑子里常问一句：**“这一段在日志里到底长什么样？”** 照着长相反推，比背语法表有效。
排错时把模式粘到 `https://regex101.com`，看哪一段被高亮吃掉，错在哪一眼就看见。

## 三、`re.compile` 到底解决什么

`re.compile` 不是“让匹配变快”那么简单（Python 内部本来就缓存最近 512 个模式，小脚本里差别测不出来）。它真正解决三件事：

1. **复用**：一行日志一个模式，编译一次，几千行反复用，不用每次把长模式重新解析。
2. **集中管理**：模式写成模块级常量 `LOG_RE`，改格式只改一处，不会散落五处漏改。
3. **把字符串升级成工具**：`str` 只是数据，`Pattern` 对象自带 `search / findall / sub`，还能当配置存起来。

## 四、五个函数的要点

| 函数 | 难点在哪 | 关键做法 |
|---|---|---|
`read_text` | 两个异常发生在**不同步骤** | `FileNotFoundError` 在打开时抛，`UnicodeDecodeError` 在读取内容时抛，不能一个 try 包住两步 |
`parse_log` | 一行四件事 | `splitlines` → `strip`（空行 continue）→ `LOG_RE.search`（None 则 dirty += 1）→ `m.groupdict()` |
`count_levels` | 无 | `Counter(r["level"] for r in records)`，或手写 `get` 累加 |
`time_span` | 不用转 datetime | `'YYYY-MM-DD HH:MM:SS'` 这种格式，**字符串比大小 = 时间比大小**，直接 `min()` / `max()` |
`module_messages` | 无 | 列表推导 `[(r["module"], r["msg"]) for r in records]` |

**三类异常各自在哪一步冒出来**：

- 文件不存在 → `open()` 那一步 → `FileNotFoundError`
- 内容是 GBK → `read()` 那一步 → `UnicodeDecodeError`
- 有脏行 → 不是异常，只是 `search` 返回 `None` → 跳过并计数

前两个是 `try/except` 的活，第三个是 `if` 的活。**能区分这两类，说明真的理解了异常机制。**
